# 旅迹 TravelTrace

面向多人结伴出游的旅游协商与行程规划系统。Android 客户端使用 Flutter，后端使用 Python / FastAPI，计划结合 DeepSeek、LangGraph、授权地图服务和约束优化。

当前阶段：目录规划。尚未初始化 Flutter 工程、安装依赖或实现后端服务。Demo 提交日期为 2026 年 12 月 15 日。

## 目录

| 路径 | 用途 |
|---|---|
| `mobile/` | Flutter Android 客户端 |
| `backend/` | FastAPI 业务服务、AI 流程和外部服务适配 |
| `contracts/` | 接口示例与约定；当前唯一 OpenAPI 源文件仍为根目录 `旅迹_OpenAPI.json` |
| `docs/` | 架构、开发、数据、测试、部署说明 |
| `data/` | 可提交的种子数据和合成测试样例；原始私密数据不入库 |
| `infra/` | Docker、反向代理等部署模板 |
| `scripts/` | 后续开发、检查和部署辅助脚本 |

详细说明见 [项目结构](docs/architecture/project-structure.md)。需求以根目录 `设计方案.md` 为准，接口以根目录 `旅迹_OpenAPI.json` 和 Apifox「旅游规划」项目为准。

## 开发分工建议

- 后端成员 A：认证、房间、消息、成员需求、协商投票。
- 后端成员 B：AI 提取、地点适配、规划、校验和行程版本。
- 客户端成员 A：登录、房间、讨论、需求确认。
- 客户端成员 B：投票、地图、行程、预算、UI 与端到端测试。

先共同确定接口与数据模型。多人通过独立分支提交修改，约定后再合并。密钥、聊天原文、数据库文件和服务器凭据不提交。

## 起步顺序

1. 初始化 FastAPI 基础工程与 Flutter 工程（Flutter 平台文件由官方工具生成）。
2. 完善账号注册和登录契约，实现房间、邀请码、加入和消息。
3. 实现成员需求提取、修改、确认及协商。
4. 接入地点服务、规划、校验和共同确认。

现有根目录 Apifox 脚本暂时保留原位。数据库迁移、自动测试和部署配置后续随实现添加。
